# Transitions swap the Plain View under one running Grid

Moving between Sections never reloads the page while the Grid is on. A link click (or back and forward) starts a Transition in the Grid Director at once. Meanwhile the next Section's own static HTML is fetched from its URL and its `<main>`, title and meta tags are swapped into the current page, and the URL is updated through the History API. The Grid has to outlive the navigation, because the old Section's pins can only tear apart under real Life if the same Life Engine is still running. Each Section stays a real static page at its own URL (ADR 0002), so the swapped content is the same HTML a reload, a crawler or a visitor with JS off gets. Nav links stay real `<a>` elements: they're laid transparently over their drawn cells, and the browser follows them normally with JS off, for new-tab clicks, or if the fetch fails.

We considered Astro's client router (view transitions) and chose a small hand-written swap. The router replaces the whole body and brings its own animations and lifecycle, while a Transition only needs `<main>` and the head's per-page styles swapped under a persistent canvas. Because pages' styles accumulate as Sections are visited, page styles must stay scoped to their own markup. Shared grid-on rules live in `Base.astro`.
